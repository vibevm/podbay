# Subsequent Codex turns

Schema v22 admits a distinct `codex.turn` command after a claimed bootstrap. Admission is durable intent, not provider insertion or completion. The authenticated host obtains a nonce-bound `codex.anchor.inspect/1` read from the live pod: its held journal must contain fsynced `BootstrapCompleted` for the original CommandId and exact native thread and Session. The old bootstrap writer lease is historical lineage. Today's manager, policy, Resource and writer lease are checked before admission and again before the native effect.

After a single store claim, the manager sends only CommandId, current Resource selectors, writer epoch and the private socket bearer. The pod reads protected text from the claimed store row; no prompt or WriterPermit crosses the socket. It rechecks manager peer, store, lease, child birth and held journals. The later-turn journal fsyncs intent before a fresh native `thread/read`, then attempts at most one `turn/start`. A valid reply fsyncs its exact native turn ID. Lost or malformed replies remain uncertain, and same-key retries read the original receipt without another port call. A matching completion notification and a separate fresh idle/no-waiting/no-pending-request read are required for fsynced terminal settlement.

Disposable fake app-server fixtures prove one second turn under the same manager, one after A→B rebind with the same child, and uncertainty without resend when the second native reply is withheld. No real model or credential content is used in those fixtures.

The current native `thread/read` and `turn/start` submission is synchronous. Pod status can block for up to the 30-second native read timeout while that RPC is in flight; the later completion pump is nonblocking. A separate nonblocking submission state machine is needed for status responsiveness throughout the entire send. `commands.get` keeps the durable `ClaimedUncertain` command/outbox receipt authoritative and attaches a read-only pod-journal stage only while the authenticated actor, current pod, store and writer lease still match. Its native terminal stage does not settle a PodBay Run or Delivery. After A→B rebind, a caller also needs a distinct read-only **current later-send guard** for its next command; the initial bootstrap guard intentionally remains restricted to writer epoch one. The private later-turn log is capped at 16 MiB / 65,536 records and fails closed at its bound; long-lived use needs a compact checkpoint or segmented successor. No steering, native question answer, permission grant, or broader process control is implied here.
