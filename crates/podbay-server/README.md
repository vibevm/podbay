# podbay-server (PB03d)

This is a preproduction **one-exchange router** with an owned Linux read socket, not a configured or running manager service. A caller supplies the durable authority and private socket directory. The listener serves authenticated `commands.get` requests serially; no provider, launch mutation, actor enrollment or automatic retry is included.

`serve_one` calls `verified_peer()` before reading the frame and again immediately before invoking the handler. The handler receives a sized `AuthenticatedTransport` wrapper that rechecks the original process and credential generation whenever host authority calls it; no cloned peer is passed as an admission witness. The handler must invoke a live authority check through that transport immediately before durable admission or any effect. The Linux `podbay.auth/1` prelude now checks an accepted Unix socket against live process evidence and a current registered actor verifier, then returns a transport with finite deadlines and repeatable peer checks. Generic `Read + Write` has no timeout contract: without adapter deadlines, a partial frame or blocked response could hold a service worker indefinitely. A production listener, actor enrollment, and a durable host handler remain separate gates.

`LinuxManagerCommandsGetListener` binds `manager.sock` only in an owner-only canonical directory, verifies the socket's file identity before each accept, and removes only its own path on explicit shutdown. Each accepted connection performs one `podbay.auth/1` proof and one read exchange; a bad connection does not end the listener. Shutdown is cooperative and waits for an active bounded exchange. The listener does not start itself or register actors.

The router accepts one bounded big-endian length-prefixed JSON frame (at most 1 MiB), then uses `podbay-wire`'s strict read or mutation decoder. Unknown version/operation, malformed JSON, wrong digest and invalid target never reach the injected handler. Valid responses use correlated `SuccessEnvelope` or `ErrorEnvelope`. If a command was admitted but its response cannot be encoded, the router returns correlated `Uncertain` with its known CommandId; a lost response preserves the original command key in `ServerFault::ResponseLost`. The caller resolves uncertainty through `commands.get` or explicit policy; this server never resends the command.

Focused router tests use an in-memory duplex stream and `PodBayClient`. Separate Linux socket tests cover actor proof, fresh process binding, verifier rotation, deadlines, malformed frames, listener lifetime, and a real Node TypeScript binding against the Rust handler. These tests do not prove a configured manager process, launch admission or provider delivery.
