# podbay-server (PB03d)

This is a preproduction **one-exchange router** with an owned Linux socket, not a configured or running manager service. A caller supplies the durable authority and private socket directory. The default listener serves authenticated `commands.get` requests serially. An explicit trusted policy can enable the narrow no-input Coordinator/Service `launch`; no provider turn, actor enrollment or automatic retry is included.

`serve_one` calls `verified_peer()` before reading the frame and again immediately before invoking the handler. The handler receives a sized `AuthenticatedTransport` wrapper that rechecks the original process and credential generation whenever host authority calls it; no cloned peer is passed as an admission witness. The Linux `podbay.auth/1` prelude checks a fresh OS process and registered verifier at the challenge boundary. After the signature, an established connection rechecks its exact actor/process/key binding without treating an unrelated authority revision as key revocation; the host still rechecks grants and manager revision before effects. Finite deadlines bound the socket exchange. Initial actor enrollment and a configured manager process remain separate gates.

`LinuxManagerCommandsGetListener` binds `manager.sock` only in an owner-only canonical directory, verifies the socket's file identity before each accept, and removes only its own path on explicit shutdown. Each accepted connection performs one `podbay.auth/1` proof and one exchange; a bad connection does not end the listener. `serve_until_with_launch` constructs a fresh deadline for each connection from a trusted relative budget, while `serve_until` stays read-only. Shutdown is cooperative and waits for an active bounded exchange. The listener does not start itself or register actors.

The router accepts one bounded big-endian length-prefixed JSON frame (at most 1 MiB), then uses `podbay-wire`'s strict read or mutation decoder. Unknown version/operation, malformed JSON, wrong digest and invalid target never reach the injected handler. Valid responses use correlated `SuccessEnvelope` or `ErrorEnvelope`. If a command was admitted but its response cannot be encoded, the router returns correlated `Uncertain` with its known CommandId; a lost response preserves the original command key in `ServerFault::ResponseLost`. The caller resolves uncertainty through `commands.get` or explicit policy; this server never resends the command.

Focused router tests use an in-memory duplex stream and `PodBayClient`. Linux socket tests cover actor proof, revision changes, verifier rotation, deadlines, listener lifetime, real Node TypeScript authentication, and launch admission/duplicate/readback through a fake host port. A separate disposable systemd test proves the actual V2 pod process path. These tests do not prove a configured manager process or provider delivery.
