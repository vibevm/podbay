# podbay-server (PB03d)

This is a preproduction **one-exchange router**, not a running manager service. A caller supplies a `Read + Write + AuthenticatedTransport` stream and a handler; no OS listener, provider, host effect or automatic retry is included.

`serve_one` calls `verified_peer()` before reading the frame and again immediately before invoking the handler. The handler receives a sized `AuthenticatedTransport` wrapper that rechecks the original process and credential generation whenever host authority calls it; no cloned peer is passed as an admission witness. The handler must invoke a live authority check through that transport immediately before durable admission or any effect. The outer adapter must perform **live process/credential reattestation** on each call, not merely replay a cached claim. It must also set finite read and write deadlines on the underlying transport. Generic `Read + Write` has no timeout contract: without adapter deadlines, a partial frame or blocked response could hold a service worker indefinitely. The production listener and peer-authentication adapter remain separate gates.

The router accepts one bounded big-endian length-prefixed JSON frame (at most 1 MiB), then uses `podbay-wire`'s strict read or mutation decoder. Unknown version/operation, malformed JSON, wrong digest and invalid target never reach the injected handler. Valid responses use correlated `SuccessEnvelope` or `ErrorEnvelope`. If a command was admitted but its response cannot be encoded, the router returns correlated `Uncertain` with its known CommandId; a lost response preserves the original command key in `ServerFault::ResponseLost`. The caller resolves uncertainty through `commands.get` or explicit policy; this server never resends the command.

Focused tests use an in-memory duplex stream and `PodBayClient`. They prove authentication precedes reads, changed peer generation prevents dispatch, invalid requests do not invoke the handler, and read/uncertain-mutation envelopes round-trip with exact request ID, command key and CommandId. These tests do not prove OS peer attestation, service lifetime, durable admission or provider delivery.
